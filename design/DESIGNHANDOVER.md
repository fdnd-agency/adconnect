# DESIGN HANDOVER ADCONNECT

A design system has been set up for ADConnect to make the interface more consistent and easier to hand over. The main inconsistencies have been identified, color tokens have been created, and a first set of reusable components has been designed.

The next team can use this design system as a basis for the further development of ADConnect.

When designing a new page, it is important to first use the existing foundations: colors, typography, spacing, and radius. After that, existing components should be used, such as the header, navigation, buttons, cards, and breadcrumbs. Only when an existing component is not sufficient should a new component be added.

A new component must always be built using the existing tokens. In addition, the component should have a clear name, and the most important states should be added, such as default, hover, active, disabled, and focus.

For developers, it is important that the token names from Figma are linked to CSS variables. This way, design and code can align better, and the interface remains consistent as the project continues to be developed.

Points of attention for the next team

The design system is a first foundation and can be further expanded. The next team can mainly continue working on:

- more component states, such as hover, focus, active, and disabled;

- further development of form fields;

- clear guidelines per component;

- further connection between Figma tokens and CSS variables;

- improvement of responsive behavior;

- cleaning up duplicate or old component variants;

- further documentation on when components should and should not be used.

With this design system, a foundation has been laid to make ADConnect more consistent and easier to hand over. The main inconsistencies have been identified, color tokens have been created, and a first set of reusable components has been set up. This allows the next team to continue building more quickly without having to create separate styles or components again.

The advice to the next team is to continue using this design system as a starting point and to always build new screens from the existing tokens and components.
